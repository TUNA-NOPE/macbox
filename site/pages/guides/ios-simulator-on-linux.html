iOS Simulator on Linux

The iOS Simulator is part of Xcode, and Xcode needs macOS, so there is no native Linux version. Web-based "iOS emulators" only imitate the look. To run the real Simulator with your own app on a Linux machine, run macOS in a VM with the GPU attached, and the Simulator inside it. macbox does that, and gives you a command, mac-sim, to drive it from Linux.

{{meta}}

In short

  • macbox runs macOS 26 with Xcode on your Linux host; the Simulator draws with Metal on your GPU.
  • ./macbox pool makes five simulators tuned for the VM; mac-sim up claims one per checkout.
  • On an Intel Arrow Lake iGPU, a 1x simulator renders a heavy Liquid Glass scene at 92 to 96 fps.

Set it up

You need a macbox VM with Xcode (macOS on Linux, then Xcode on Linux). Then, on the host:

./macbox pool             # create the simulator pool in macOS
./macbox agents install   # mac-sim, sim-fps, android-sim in ~/.local/bin, the idle timer

The pool

Instead of many default simulators, macbox keeps a small pool built for a VM. Each one is named <iPhone> (macbox <kind>), for example iPhone 17 Pro (macbox slim 1).

KindPixelsUse it for
slim-1, slim-21xmost work. About 170 background iOS services are off (about 0.6 GB of memory instead of about 2), and it animates fastest
full1xwidgets, Live Activities, the Dynamic Island, push notifications: every iOS service runs
sharp3xscreenshots at a real iPhone's pixels
small3xsmall-phone layouts (the "e" iPhone)

The 1x simulators have the same layout in points as a real iPhone with a quarter of 2x's pixels, which is why they are the default. Use the 3x ones for stills, not for judging frame rates.

Use it

Run mac-sim from inside an app's checkout. Each checkout (git root) gets its own simulator and keeps it until down, so parallel worktrees don't wait for each other.

mac-sim up                  # claim a slim simulator and boot it (--full, --sharp, --small)
mac-sim run                 # build the app on the Mac, install and open it; Metro runs here
mac-sim snapshot            # the screen as an accessibility tree, refs like @e12
mac-sim ad press @e12       # tap; any agent-device command
mac-sim open myapp://path   # a deep link
mac-sim shot /tmp/home.png  # a lossless screenshot, copied to Linux
mac-sim record /tmp/a.mp4 10   # 10 s of video
sim-fps /tmp/a.mp4          # fps and dropped frames per stretch of motion
mac-sim status              # every simulator and who holds it
mac-sim down                # give it back

mac-sim install path/To.app installs any simulator build, and mac-sim mac '<command>' runs a shell command on the Mac with $UDID set to your simulator, so plain xcrun simctl works too.

See the screen

  • Screenshots and recordings from mac-sim shot and record arrive on Linux, at the simulator's own pixels.
  • T3 Code's Device panel streams the simulator live and takes taps: ./macbox t3 register, then ./macbox t3 fix-hub. docs/t3-code.md has the details.
  • The macOS desktop in a browser tab (http://127.0.0.1:6081/) or a local window, if you want Simulator.app. Keep it closed otherwise: it opens a window per simulator and doubles the GPU's work.

How fast it is

Measured with GlassBench, a table scrolling under Liquid Glass bars and a floating glass toolbar, counted at the simulator's own screen, on an Intel Core Ultra 7 265 (Arrow Lake iGPU) with Mesa 26.2.4, macOS 26.7.1 and iOS 26.5:

SimulatorReims upstream (2ce3209)macbox build
1x (402×874)53.5 fps95.8 / 92.5 fps
2x (804×1748)33.5 fps67.8 / 60.5 fps
3x (1206×2622)17.2 fps38.5 / 39.5 fps

The GPU sets the ceiling: a 3x simulator keeps that iGPU 96 to 98% busy. Simulators animating at the same time share it. Recording uses the VM's software H.264 encoder, about 50 fps with one simulator animating. Full method: docs/performance.md.

Limits

  • iOS 26 Simulators are the newest on x86-64; iOS 27's simulators are Apple silicon only.
  • Simulator resolutions are fixed once created; pick a different pool simulator instead.
  • Don't restart CoreSimulatorService while simulators run: it shuts down every one of them.
  • Pool simulators idle for 20 minutes (no mac-sim command, no viewer) are shut down by a timer.
