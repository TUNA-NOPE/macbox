How to run macOS on Linux with GPU acceleration

macOS runs well in a KVM virtual machine on Linux. The usual catch is graphics: without a GPU passed through to the VM, macOS draws in software, and anything built on Metal is slow or broken. macbox solves that with Reims vGPU, and wraps the whole setup in one command-line tool.

{{meta}}

In short

  • You need an x86-64 Linux host with KVM, AVX2, an Intel or AMD GPU with a Mesa Vulkan driver, 16 GB of RAM, about 150 GB of SSD, and Docker.
  • ./macbox init, doctor, build, create, up, then a short install in the VM's screen. ./macbox next always prints the next step.
  • The result is macOS 26 Tahoe with Metal on your GPU, reachable as ssh macbox and as a window or browser tab.

How it works

macbox runs QEMU inside a Docker container, with KVM for the CPU. Booting macOS on a PC goes through OpenCore, which reims-ctl sets up. The part that is different from other macOS-on-Linux setups is the GPU:

  • Reims vGPU gives QEMU Apple's paravirtual GPU device (apple-gfx-pci). macOS already has a driver for it, so no guest driver is needed.
  • metal2vulkan runs the Metal work that device receives on Vulkan, through Mesa on your GPU.
  • The host keeps its GPU. Nothing is passed through, and an integrated GPU is enough.

macbox builds both from pinned commits with its own patches, which made the iOS Simulator 1.8 to 2.3 times faster on the GPU they were measured on. The GPU guide explains the path in detail.

Requirements

CPUx86-64 with VT-x or AMD-V, and AVX2
GPUIntel (measured: Arrow Lake iGPU) or AMD (supported by Reims, untested here), with a Mesa Vulkan driver. macbox's image doesn't ship NVIDIA's driver yet
RAM16 GB or more; the VM takes 8 to 16
Diskabout 150 GB free on an SSD or NVMe
SoftwareKVM (/dev/kvm), a render node (/dev/dri/renderD*), Docker (rootless works well) or Podman (untested)

The guest is macOS 26 Tahoe. Apple's last macOS for Intel is 26, so that is also the newest macOS that runs on x86-64.

Apple's software license agreement for macOS allows it to run only on Apple-branded hardware. Running it in a VM on other hardware breaches that agreement. macbox ships no Apple software; macOS downloads from Apple, and complying with Apple's terms is up to you.

1. Prepare the host

Your user needs to open /dev/kvm and the GPU's render node, and Reims needs a much higher vm.max_map_count than the default 65530:

sudo usermod -aG kvm,render $USER        # then log in again
echo vm.max_map_count=2097152 | sudo tee /etc/sysctl.d/60-macbox.conf && sudo sysctl --system

With more than one GPU, choose the render node in the config (MACBOX_RENDER_NODE). An AMD GPU also needs access to /dev/udmabuf.

2. Configure, check and build

git clone https://github.com/TUNA-NOPE/macbox ~/macbox && cd ~/macbox
./macbox init      # ~/.config/macbox/macbox.env, an SSH key, a "Host macbox" alias
./macbox doctor    # fix every FAIL; WARN lines are advice
./macbox build     # the image, then Reims vGPU + metal2vulkan + QEMU: 20 to 60 minutes, ~25 GB

init sizes the VM for your machine (half the cores, a third of the RAM, within limits). Look at ~/.config/macbox/macbox.env before you build: the resolution, CPU pinning for hybrid CPUs, and where everything is stored (MACBOX_HOME) are all set there.

3. Create the VM and install macOS

./macbox create          # the newest macOS 26 Tahoe, through Apple's recovery image
./macbox boot-picker on  # OpenCore's boot menu, needed for one Recovery step
./macbox up

Open the screen at http://127.0.0.1:6081/ in a browser on the host, or run ./macbox view local from a Wayland desktop on the host for a window with no encoding at all. Then, in the VM:

  1. In Recovery, open Disk Utility, choose View › Show All Devices, and erase QEMU HARDDISK Media as APFS with a GUID partition map.
  2. Choose Reinstall macOS and install onto that disk. It downloads macOS from Apple and restarts a few times (30 to 60 minutes).
  3. When Setup Assistant or a broken desktop appears, restart the VM (./macbox down && ./macbox up), choose Recovery in OpenCore's menu, open Utilities › Terminal, and run ./macbox recovery-fix on the host. It sets the Metal error mode macOS 26 needs under Reims.
  4. Go through Setup Assistant: skip the Apple Account and create an administrator named dev.
  5. Open Terminal in macOS and run ./macbox ssh-bootstrap on the host. Then ssh macbox sw_vers should answer.

Each of these steps is spelled out, with what to do when one goes wrong, in docs/setup.md. An AI agent can do them too: it sees the screen with ./macbox screenshot and acts with click, type and key (AGENTS.md).

4. Finish over SSH

./macbox down && ./macbox disk nvme && ./macbox boot-picker off && ./macbox up
./macbox provision                            # passwordless sudo, no sleep, Node, Ruby + CocoaPods
./macbox xcode ~/Downloads/Xcode_26.6.xip     # optional: Xcode and the iOS Simulator runtime
./macbox pool                                 # optional: the iOS Simulator pool
./macbox agents install                       # optional: mac-sim, sim-fps and the skills

Moving the system disk to NVMe makes small reads about a third faster and app launches up to twice as fast. ./macbox next ticks off each step as it's done.

Day to day

./macbox up | down | status
./macbox ssh                       # a shell on the Mac
./macbox logs qemu                 # or selkies, sway
./macbox resolution 2560x1440      # macOS's screen size (restarts a running VM)
./macbox backup before-update      # a copy of the disk, with the VM stopped

To watch from another machine, forward the port (ssh -L 6081:127.0.0.1:6081 <host>) or publish it on a private tailnet. The stream has no password of its own, so never expose it on the open internet.

Limits

  • macOS 26 is the ceiling on x86-64; macOS 27 and iOS 27's simulators are Apple silicon only.
  • NVIDIA GPUs aren't supported by macbox's image yet. AMD should work through Reims, but hasn't been tested with macbox.
  • An idle macOS display gets no vblank from its driver, so the first frame of an animation starts about 0.1 s late (reims-vgpu#141).

When something doesn't work, start with ./macbox doctor and docs/troubleshooting.md.
