How to run Xcode on Linux

There is no Xcode for Linux, and no Linux tool that replaces it for iOS: building, signing and simulating Apple apps needs Apple's SDKs, which run on macOS. What you can do is run macOS itself on your Linux machine, and the real Xcode inside it. This guide does that with macbox.

{{meta}}

In short

  • Set up a macOS VM with macbox (guide).
  • Download Xcode 26's .xip from Apple, then ./macbox xcode ~/Downloads/Xcode_26.6.xip.
  • Build from Linux with ssh macbox xcodebuild …, or use Xcode's window in the VM's screen.

Which Xcode runs

Xcode 26, with iOS 26 Simulators. macbox's macOS guest is x86-64, and macOS 26 Tahoe is the last macOS for Intel. Apple ships macOS 27, Xcode 27 and iOS 27's simulators for Apple silicon only, so they can't run on an x86-64 Linux host. macbox is used day to day with Xcode 26.6 and iOS 26.5.

Install Xcode

  1. Set up the VM as in How to run macOS on Linux, through ./macbox provision. You need ssh macbox working.
  2. Download Xcode's .xip from developer.apple.com/download/all. Any free Apple Account can sign in there. macbox never handles your Apple ID, so this one step is yours, on the host.
  3. Install it: 
    ./macbox xcode ~/Downloads/Xcode_26.6.xip
./macbox xcode     # afterwards: the version, license and first-launch status
    It copies the file into the VM, expands and installs it, selects it with xcode-select, accepts the license, runs the first launch, and adds the iOS Simulator runtime. Expect 30 to 60 minutes.

Build from Linux

The VM is an SSH host named macbox, so Xcode's command-line tools are one hop away:

ssh macbox xcodebuild -version
ssh macbox xcrun simctl list devices available

Copy a project in with rsync or git clone it on the Mac, then run xcodebuild as you would on a Mac. For Expo and React Native apps, mac-sim run does the copy, the CocoaPods install, the build and the install into a simulator for you, with Metro on Linux: see the Expo guide.

To use Xcode's own window, open the VM's screen at http://127.0.0.1:6081/ or run ./macbox view local. Xcode draws with Metal on your GPU like the rest of macOS.

Simulators and devices

  • ./macbox pool creates a small pool of iOS Simulators tuned for the VM, mostly at 1x pixels, which is 4 to 9 times cheaper to draw than 3x. See iOS Simulator on Linux.
  • Keep Simulator.app closed when you can. It opens a window per booted simulator and doubles the GPU's work; mac-sim and T3 Code read the simulator's screen directly.
  • For an .ipa on a real iPhone or TestFlight, the phone-build tool builds in the VM (after Expo's free EAS cloud builds). Signing for devices needs Apple's paid Developer Program.

Common questions

Do I need an Apple Account inside macOS?

No. Setup Assistant can skip it. You only sign in at developer.apple.com, in your own browser, to download the .xip.

Is it fast enough to use?

On an Intel Arrow Lake iGPU, a 1x iOS Simulator renders a heavy Liquid Glass scene at 92 to 96 fps. Builds use the VM's vCPUs (8 in that setup); a first Expo build takes 2 to 15 minutes and later builds are incremental. Other hardware hasn't been measured yet.

Is it legal?

Apple's macOS license allows macOS only on Apple-branded hardware, so running it in a VM on a PC breaches that agreement. macbox ships no Apple software, and compliance with Apple's terms is your responsibility.
