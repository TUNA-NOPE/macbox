macOS, Xcode and the iOS Simulator on Linux, drawn on your own GPU

macbox runs a full macOS VM in Docker on a Linux machine, with Metal accelerated by the host's GPU through Reims vGPU. It installs Xcode and a pool of real iOS Simulators that you, or an AI coding agent such as Claude Code or Codex, can build on, run, tap, screenshot and measure at 60 fps. No Mac, no cloud service, no per-minute bill.

What you get

A real Mac toolchain on a Linux box

Everything Xcode needs runs inside a genuine macOS guest. macbox adds the parts that make it fast and usable from Linux and from agents.

macOS with Metal

Reims vGPU gives QEMU Apple's paravirtual GPU, so macOS's own driver works with no guest driver. metal2vulkan runs Metal's work on Vulkan.

Xcode and its tools

macbox xcode installs the Xcode .xip you download from Apple, accepts the license and adds the iOS Simulator runtime. xcodebuild and CocoaPods run over SSH.

A pool of iOS Simulators

Slim 1x simulators for most work, a full one for widgets, Live Activities and the Dynamic Island, and a 3x one for real iPhone pixels.

Built for AI coding agents

mac-sim gives each checkout its own simulator: build, run, tap, type, lossless screenshots and video. sim-fps checks a recording held 60 fps.

The screen, anywhere

A window on your Linux desktop with no encoding, or a browser tab (Selkies, H.264 on the GPU). Agents can see and click it too: macbox screenshot, click, type.

T3 Code, Expo and Android

Simulators stream live into T3 Code's Device panel. Expo and React Native apps build on the Mac with Metro on Linux. android-sim runs Android emulators on the host.

Official support

Made for AI coding agents and T3 Code

AI coding agents and T3 Code are first-class, officially supported in macbox: the integrations ship in the repository, are installed with one command, and are maintained with the rest of the project.

Claude Code

The simulators, phone-builds and macbox skills, a Simulators section in CLAUDE.md, and an optional hook that points it at the skill whenever a prompt mentions a simulator.

Codex

The same skills in ~/.agents/skills and the same section in ~/.codex/AGENTS.md, so Codex builds, taps, screenshots and measures the app on its own.

T3 Code

macbox t3 register adds the VM to T3 Code's Device panel and macbox t3 fix-hub rebuilds T3's device hub for the Intel VM: the simulator streams live and takes taps, and agents open it with device_open.

./macbox agents install   # mac-sim, sim-fps, android-sim, the skills and instructions for Claude Code and Codex
./macbox t3 register      # the VM in T3 Code's Device panel (then: ./macbox t3 fix-hub)

Every agent checkout gets its own simulator, and the skill's loop has the agent run the app, look at a screenshot, record the flow and check with sim-fps that it held 60 fps before calling a UI change done. The agents and T3 Code guide →

How it works

One container, one VM, your GPU

  1. A container holds the whole stack. Ubuntu with Mesa, QEMU built with Reims vGPU, a headless compositor and the browser stream. It keeps nothing of its own; the VM lives on your disk.
  2. macOS draws with Metal. QEMU exposes Apple's paravirtual GPU. Reims vGPU answers it on the host, and metal2vulkan translates the Metal work to Vulkan on your Intel or AMD GPU.
  3. Everything else is SSH. After a short GUI install, Xcode, the simulator pool and the agent tools are set up with commands. mac-sim copies a checkout into macOS, builds it there and runs Metro on Linux.

Requirements

What you need

CPUx86-64 with VT-x or AMD-V, and AVX2
GPUone with a Mesa Vulkan driver: Intel (measured on an Arrow Lake iGPU) or AMD (supported by Reims, untested here). NVIDIA works with Reims, but macbox's image doesn't ship NVIDIA's driver yet
RAM16 GB or more (the VM takes 8 to 16)
Diskabout 150 GB free, on an SSD or NVMe
OSLinux with KVM (/dev/kvm), a render node (/dev/dri/renderD*), and Docker (rootless is fine) or Podman

macOS for Intel ends with macOS 26 Tahoe, and Apple ships iOS 27's simulators for Apple silicon only. So macbox runs macOS 26, Xcode 26 and iOS 26 simulators: that is the ceiling on x86-64.

Quick start

Up in an afternoon

git clone https://github.com/TUNA-NOPE/macbox && cd macbox
./macbox init      # config, an SSH key, the ssh alias "macbox"
./macbox doctor    # checks KVM, the GPU, Docker, disk space
./macbox build     # Reims vGPU + metal2vulkan + QEMU (20 to 60 min)
./macbox create    # a VM; macOS downloads from Apple
./macbox up        # the screen: http://127.0.0.1:6081/
./macbox next      # what's done, and the next step

Installing macOS takes a few steps in the VM's screen, then the rest is commands: provision, xcode, pool, agents install. Plan on two to three hours, mostly downloads and builds. An agent can do the whole setup, GUI steps included: point it at AGENTS.md.

FAQ

Questions people ask

Can I run the iOS Simulator on Linux?

Not by itself: it's part of Xcode, which needs macOS. macbox runs macOS in a VM on Linux with the GPU attached, so the real Simulator runs on your own machine, with no Mac, no cloud account and no per-minute bill.

How do I give Claude Code or Codex an iOS Simulator on a Linux server?

Set up macbox, then run macbox agents install. Agents get mac-sim (a simulator per checkout: build, run, tap, screenshot, record), sim-fps (did that animation hold 60 fps?), and a skill that tells them when and how to use them. See the agents guide.

Is this Docker-OSX or OSX-KVM with GPU acceleration?

Those boot macOS in QEMU too, but macOS gets Metal only when you pass a GPU it has drivers for through to the VM (VFIO), which takes that GPU away from the host. macbox uses Reims vGPU instead: Apple's own paravirtual GPU device, run on the host's Vulkan driver. The host keeps its GPU, macOS gets Metal, and an integrated GPU is enough.

Can I build and run an Expo or React Native iOS app on Linux?

Yes. mac-sim run copies the checkout into macOS, builds it with Xcode and CocoaPods, and installs it in the simulator. Metro runs on Linux, so JavaScript edits arrive by Fast Refresh. The Expo guide covers Release builds and Expo Go.

Does it work with T3 Code's Device panel?

Yes: macbox t3 register adds the VM as a device host, and the simulators stream live into the panel and take taps.

Real iPhones and TestFlight?

phone-build makes .ipa builds (Expo's free EAS cloud builds first, then locally in the VM) and uploads to TestFlight. Signing for devices needs Apple's paid Developer Program.

What can't it do?

Run macOS 27, Xcode 27 or iOS 27's simulators, which Apple ships for Apple silicon only. And it can't make running macOS on non-Apple hardware compliant with Apple's license: see below.

Is it free?

For noncommercial use, yes: macbox's own code is under the PolyForm Noncommercial License 1.0.0 (yourself, a hobby, research, teaching, a charity). Commercial use needs the author's permission: open an issue to ask.

Apple's license. macbox ships no Apple software. macOS, Xcode and the simulator runtimes download from Apple under Apple's terms, and you alone are responsible for complying with them. Apple's software license agreement for macOS allows it to run only on Apple-branded hardware; running it in a VM on other hardware breaches that agreement. macbox comes as is, with no warranty.
